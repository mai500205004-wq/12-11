Section 03 'chna' & 'axml' Metadata Usage Definition
ITU-R BS.2076-2 // ADM PROFILE
'chna' (Channel Allocation Chunk) ITU-R BS.2076

The chna chunk links audio channels within a RIFF container to Audio Definition Model (ADM) format descriptors. It is NOT mandatory for conventional discrete monophonic stems. For this handover profile, discrete monophonic delivery does not automatically mandate Dolby Atmos or ADM metadata headers.

Track Allocation Mapping:
A1: Track UID 0001 (Mono Vance) A2: Track UID 0002 (Mono Resp) A3: Track UID 0003 (Mono Thruster) A4: Track UID 0004 (Mono RF)
'axml' (Audio XML Chunk) EBU Tech 3285 s3

Carries standard XML-formed representations of ADM scene definitions, audioPackFormats, or extended production provenance. Optional in monophonic delivery pipelines; entirely distinct from Avid AAF MXF descriptors and broadcast iXML metadata blocks.

Parsing Priority Chain:
1. bext → 2. iXML → 3. axml (if ADM flag active)
Container Architecture Differentiation Matrix
BWF Metadata Architecture (RIFF) FOURCC CHUNKS
  • fmt: Audio format specification, channels (0x0001), sample rate, bits/sample.
  • data: Raw interleaved or monophonic PCM audio essence payload.
  • bext: Broadcast extension containing TimeReference samples, date/time, coding history.
  • ixml: Electro-acoustic scene, take, tape, track naming, and circular recorder telemetry.
  • chna: ADM multichannel UID references (optional for discrete mono).
MXF OP-Atom Architecture (SMPTE 390M) SMPTE KLV SYSTEM
  • Header Partition: Open/Closed partition packs establishing essence boundaries.
  • Preface & Identification: Generation UID, product version, platform signature.
  • Material Package (MasterMob): Logical project representation mapped inside Avid.
  • File Package (SourceMob): Physical track package binding audio track to essence.
  • Sound Essence Descriptor: Quantization, audio sampling rate, channel count (1).
